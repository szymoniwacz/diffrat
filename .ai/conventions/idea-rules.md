# Idea Rules

## Purpose

Ideas are captured before implementation starts.

This prevents early coding without a clear reason.

## Idea lifecycle

| Status | Meaning |
|---|---|
| active | raw or early idea |
| expanded | described enough to plan |
| implemented | completed later in the project |
| archived | rejected or deferred |

## Rules

1. Every idea gets its own file.
2. Every idea has a short title.
3. Every idea describes the problem before the solution.
4. Expanded ideas include scope and non-goals.
5. Normal feature work follows `.ai/workflows/feature.md` after requirements
   and scope are confirmed.
6. A clear task already derived from accepted requirements may start at the
   task-packet stage without a new idea file.
7. Bugfixes and small documentation edits do not require fake idea files.
8. Moving an idea between folders updates `.ai/ideas/README.md`.

## Naming

Use this pattern:

`001-short-kebab-title.md`
